# 技术方案

## 整体架构

```
用户浏览器 (H5)         后端服务器               AI服务
┌──────────────┐     ┌──────────────┐     ┌────────────┐
│  React SPA   │────▶│ Python       │────▶│ DeepSeek   │
│  (Vite)      │     │ FastAPI      │     │ V4 Pro     │
│              │     │              │     │ (文本分析) │
│  localStorage│     │ EasyOCR      │     └────────────┘
│  (会话/档案) │     │ (图片→文本)  │
└──────────────┘     └──────────────┘
     ▲                     │
     └─────────────────────┘
        JSON API 通信
```

## 技术选型

### 前端
| 项 | 选择 | 原因 |
|----|------|------|
| 框架 | React 19 + TypeScript | 生态成熟，适合SPA |
| 构建 | Vite | 快速开发体验 |
| 样式 | Tailwind CSS v4 | 快速实现卡片化设计 |
| 路由 | 无路由库 | App 内 phase 状态机（列表/上传/结果/历史/设置/loading） |
| 状态 | React useState + localStorage | 轻量，无需Redux |
| HTTP | fetch API | 零依赖 |
| 存储 | localStorage | 会话/档案，PRD要求 |

### 后端
| 项 | 选择 | 原因 |
|----|------|------|
| 框架 | FastAPI | 异步支持好，自动API文档 |
| OCR | EasyOCR | 中文识别率高，离线可用 |
| HTTP | httpx (异步) | 调用DeepSeek API |
| 图片处理 | Pillow | 图片预处理提高OCR准确率 |

### AI
| 项 | 选择 | 说明 |
|----|------|------|
| 分析/生成 | DeepSeek V4 Pro | 用户提供API Key |
| 图片识别 | EasyOCR (后端) | DeepSeek V4 Pro不支持视觉 |

## API 设计

### POST /api/analyze
请求：1-5张图片(multipart form-data) + 关系阶段 + 目标 + 回复风格 + crush档案摘要 + swap_sides(气泡纠错)
返回：结论 + 军师思考 + 6条回复建议 + 翻车预警 + 会话摘要 + 档案更新

## 数据流
1. 用户选择图片 → FormData 上传（multipart）
2. POST /api/analyze → 后端 EasyOCR 提取文本（swap_sides=true 时交换左右标注）
3. 构建 prompt（含 crush 档案摘要）→ DeepSeek API 分析
4. 解析结构化JSON → 返回前端渲染
5. 分析后 → localStorage 更新会话：crush_profile_summary 滚动记忆 + 追加一条分析记录（历史）

## 本地存储（localStorage）
- `duxin_sessions`：会话数组，每条含 `records[]`（多轮分析记录）
- `duxin_session_counter`：自动命名计数器
- 不存原始截图，仅存分析文本摘要

## 安全设计
- API Key 仅通过环境变量读取，不出现在前端代码
- 图片处理完即丢弃，不写磁盘
- 日志不记录 base64 图片和完整请求内容
- 前端仅存储分析文本摘要，不存原图
