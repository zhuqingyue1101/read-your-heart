# 开发计划

## Phase 划分原则
- 每个 Phase 完成后可独立验证
- 环境变量/API Key 在 Phase 1 就配置好
- 安全约束从第一天就遵守

---

## Phase 1: 项目骨架 + 后端 OCR + DeepSeek 对接

**目标**: 能上传1张截图 → 后端OCR提取文本 → DeepSeek分析 → 返回JSON结果

**任务**:
- [ ] 初始化 frontend (Vite + React + TS + Tailwind)
- [ ] 初始化 backend (FastAPI + EasyOCR)
- [ ] 配置 DEEPSEEK_API_KEY 环境变量
- [ ] 实现 POST /api/analyze（OCR + DeepSeek prompt + JSON解析）
- [ ] 前端最简上传页 + 结果展示页
- [ ] 验证端到端流程

**验收**:
- 上传1张微信聊天截图 → 看到结果JSON中的结论、回复

---

## Phase 2: 完整分析链路

**目标**: 支持1-5张图、上下文选择、完整输出

**任务**:
- [ ] 前端上传1-5张图，预览/删除/排序
- [ ] 上下文选择页（关系阶段 + 目标 + 回复风格）
- [ ] DeepSeek prompt 优化（含 few-shot 示例）
- [ ] 读心结果页完整渲染（结论 + 军师思考）
- [ ] 回复建议页（6条回复卡片 + 复制）
- [ ] 翻车预警模块
- [ ] 气泡识别错误手动切换

**验收**:
- 完整走通：选择截图 → 选上下文 → 看结果 → 复制回复

---

## Phase 3: 本地存储 + 连续关系感

**目标**: localStorage 档案 + 继续分析

**任务**:
- [ ] crush档案 CRUD（创建、选择、编辑、删除）
- [ ] 每次分析自动更新档案 summary
- [ ] 继续分析流程（基于档案历史 + 新截图）
- [ ] 历史记录详情页
- [ ] 数据清除功能

**验收**:
- 创建crush档案 → 分析 → 刷新页面档案仍在 → 继续分析有上下文

---

## Phase 4: 优化打磨

**目标**: 体验完善，准备发布

**任务**:
- [ ] 加载骨架屏 + 有趣 loading 文案
- [ ] 错误处理完善（OCR失败、API异常、网络超时）
- [ ] 移动端适配打磨（触摸体验、安全区域）
- [ ] 图片压缩（前端压缩后上传）
- [ ] OCR 准确率优化（图片预处理）
- [ ] 隐私提示完整展示

**验收**:
- 首次用户30秒内完成操作
- 所有异常场景有友好提示
- 回复自然度盲测通过
