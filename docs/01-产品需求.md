# 产品需求文档摘要

> 完整PRD见项目根目录：`读心V2 产品需求文档.pdf`

## 产品定位
AI暧昧聊天截图解读工具。用户上传与crush的聊天截图，系统判断对方信号、分析关系局势，给出可直接复制的回复建议。

## 核心场景
用户上传和crush的聊天截图 → 看懂对方什么意思 → 生成下一句怎么回

## 目标用户
18-28岁年轻人，活跃于小红书/抖音/微信，处于暧昧期、追人期、复联期或约会后观察期。

## V2 核心目标
1. 看懂局势：判断TA是在试探、暧昧、冷淡、推进还是客套
2. 给出自然回复：像真人微信会发的话，不像AI
3. 连续关系感：本地crush档案记录关系进展

## 功能范围

### 包含
- 上传1-5张聊天截图（jpg/png/webp，单张≤10MB）
- 图片排序（调整顺序）+ 超过5张提示
- 上下文选择（关系阶段、目标、回复风格）
- 读心结果（一句话结论 + 军师思考）
- 回复建议（6条，可复制）
- 翻车预警
- 气泡识别纠错（切换双方重新分析）
- 本地crush档案（localStorage）
- 会话列表（同时管理多条crush关系线）
- 续读分析（同一crush持续分析，自动带入档案摘要）
- 历史记录（多轮分析记录，可查看/删除单条）
- 设置页（清除全部数据 / 删除单个档案）

### 不包含
- 登录注册、云端数据库、付费系统、社区、App上架

## 核心输出
1. 一句话结论：以"我觉得/emmm我觉得/我感觉/说实话我觉得"开头
2. 军师思考：≤200字
3. 回复建议：6条，5-25字为主，自然口语化
4. 翻车预警：不建议发送的话+原因

## 会话列表与续读

用户往往不只聊一个人，也不会聊一次就结束。会话列表把「一次分析」升级成「一条持续的关系线」：每条会话对应一个 crush，记录关系背景与进展，下次直接接着问「对方又回话了，怎么回」。

### 用户流程
1. 首页 = 会话列表，展示所有 crush 关系线（备注名 + 关系阶段 + 上次结论 + 更新时间）
2. 「＋ 新建会话」→ 填写可选备注名 → 上传截图 → 选择上下文 → 出结果
3. 结果页「对方回了吗？接着读」→ 回到上传页，阶段/风格/备注名/档案摘要已自动带入，只传新截图
4. 点列表卡片 → 直接进入该条线的续读上传
5. 「回列表」保存并返回；刷新页面数据仍在（localStorage）

### 会话数据（仅存 localStorage）
每条会话保存：备注名、关系阶段、目标、回复风格、crush 档案摘要（用于续读衔接上文）、上次结论、创建/更新时间。

### 关键规则
- 续读只传对方最新的回复截图，之前的来龙去脉由档案摘要承接（避免重复上传旧图、控制 token）
- 每次分析成功后，用新的 crush 档案摘要覆盖旧摘要，形成滚动记忆
- 备注名可选，为空时自动命名「Crush N」
- 删除会话即永久清除该条线（含档案）

## 历史记录、设置与纠错

### 历史记录
- 每次分析都存一条记录（结论、军师思考、回复建议、翻车预警、会话摘要），不存原始截图
- 列表卡片底部「历史记录（N）」进入详情页，按时间倒序展示，可展开看全文、删除单条
- 历史详情页顶部可「继续读这条线」

### 设置页
- 列表页右上角 ⚙️ 进入
- 删除单个 crush 档案（含该线全部历史）
- 清除全部本地数据（二次确认，不可恢复）

### 气泡识别纠错
- 结果页底部「气泡识别错了？切换双方重新分析」
- 用原图重新分析并交换左右标注，覆盖上一次结果（不新增历史），可来回切换

## 技术原则
- 不接数据库、不做登录
- 不保存截图到服务端
- crush档案和历史只存localStorage
- API Key 仅在后端环境变量
